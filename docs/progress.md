- [ ] **클라이언트 IP 판정**: 지금 `ClientIp`는 `request.getRemoteAddr()`를 그대로 쓴다. 운영에서 Caddy 뒤에 두면 모든 요청이 프록시 IP로 보여 **전체 사용자가 같은 레이트 리미트에 묶인다**(로그인 10분 30회를 모든 사용자가 나눠 씀). - [ ] **운영용 메일 발송 구현(M5)**: 없으면 prod 프로필로 앱이 기동하지 않는다 (ADR-010).

- [ ] **탈퇴 후 카카오 회원번호 보관**: 탈퇴 후 30일이 지나 연결 끊기에 실패한 카카오 회원번호를 대기 테이블(`kakao_unlink_pending`)에 보관하는 것이 적법한지, 보관 기간을 어떻게 볼지(끊기에 성공하면 바로 삭제). 쟁점: 카카오 공식 문서는 탈퇴 시 연결 끊기를 반드시 하라고 하면서, user_id도 파기 대상 개인정보라고 한다. 이 둘을 어떻게 맞출지 (ADR-015).

## 배포 후 검토
- [ ] **카카오에서 이메일 받기(비즈 앱 전환)**: 지금은 이메일 동의항목(`account_email`)이 "권한 없음"이라 scope에서 뺐고, 알림 이메일은 가입 단계에서 직접 입력받는다(아래 "M1-c 브라우저 확인 중 변경"). 카카오에서 이메일을 받으려면 비즈 앱(개인 개발자 비즈 앱) 전환과 동의항목 설정이 필요하다. 비즈니스 정보 심사에 서비스 정보와 개인정보처리방침이 필요할 수 있다. 닉네임 동의항목을 개발자 외의 사용자도 쓸 수 있는지도 함께 확인한다. 다시 켜려면 `app.kakao.scopes`에 `account_email`을 더한다 (ADR-014).

### M1-a에서 확정한 결정
- 이메일 컬럼: `email` 하나 + `auth_provider`(LOCAL/KAKAO), **LOCAL 계정끼리만 unique**. 앱에서 소문자 정규화 + DB CHECK로 강제 (ADR-006)
- 중복 이메일 가입 시 "이미 가입된 이메일이에요"로 안내. 계정 존재 노출 위험은 M1-b IP 레이트 리미트로 완화
- BCrypt cost 12, `{bcrypt}` 접두사(DelegatingPasswordEncoder)
- 세션 유휴 타임아웃 2시간, 쿠키 `HttpOnly`·`Secure`(로컬도 true)·`SameSite=Lax`
- 가입 직후 바로 로그인
- 가입 폼: 이메일, 비밀번호, 비밀번호 확인, 이름(호칭), 약관·처리방침 필수 동의(검증만, 기록은 M1-c)
- 흔한 비밀번호 목록은 직접 정리한 약 100개
- 세션 principal 이름은 이메일이 아니라 landlord id

### M1-a 구현 결과 메모 (2026-10-17)
- 마이그레이션: V2 `landlord`, V3 Spring Session 테이블(공식 스크립트 그대로). ADR-005~009 작성.
- 세션 설정은 `spring.session.timeout`과 `SessionCookieConfig`(CookieSerializer 빈) 한 곳에만 둔다. Boot가 MockMvc와 실제 실행에서 `server.servlet.session.*`를 다른 경로로 읽기 때문이다 (ADR-005). 실제 Tomcat 테스트는 `SessionCookieRealServerTests` 1개뿐.
- `thymeleaf-extras-springsecurity6`는 Security 7.1.1에서 `sec:authorize`·`sec:authentication`이 동작하는 것을 테스트로 확인했다 → `@ControllerAdvice` 대체는 필요 없었다.
- 기본 거부(`denyAll`) 때문에 비로그인 상태로 없는 주소에 가면 404가 아니라 로그인 화면으로 간다(로그인 상태면 403). 404 화면은 `/css/no-such.css`처럼 허용 경로 안의 없는 파일에서 보인다 (ADR-008).
- Tailwind 4.3.3 Windows 바이너리는 이 PC에서, Linux 바이너리는 CI(PR #2)에서 동작 확인.
- Windows의 `curl.exe`로 한글 폼 값을 명령줄에서 보내면 CP949로 바뀌어 Tomcat이 400을 준다. 브라우저(UTF-8)는 정상이다. curl로 시험할 때는 `%EA%B2%80`처럼 UTF-8 퍼센트 인코딩 값을 직접 넣는다.
- 확인 완료: 개발자 브라우저 확인(가입→로그인→로그아웃, 쿠키 속성, 404 화면), CI 통과, PR #2로 main 병합.

### M1-b 구현 결과 메모 (2026-10-17)
- 마이그레이션: V4 `account_token` + `landlord.email_verified_at`, V5 `login_failure`·`rate_limit_bucket`, V6 `persistent_logins`. ADR-010~013 작성.
- 개발 메일: bootRun 콘솔에서 로거 `rentkeeper.dev-mail`의 `===== [개발용 메일 - 실제로 발송되지 않음] =====` 블록에 인증·재설정·이메일 변경 링크가 찍힌다 (local 프로필 전용, ADR-010).
- 계획 대비 확인 결과:
  - `CookieTheftException`: Security 7.1.1 기본 동작은 500 → `HashingRememberMeServices`에서 잡아 로그인 화면 안내로 처리 (ADR-013).
  - 자동 로그인 후 세션 저장, Tomcat의 remember-me `SameSite=Lax` 출력: 테스트로 확인.
  - **remember-me 키를 바꿔도 기존 로그인 유지는 풀리지 않는다** (PersistentToken 방식). 모두 끊으려면 `persistent_logins`를 비운다. 키를 바꾸면 모두 무효가 된다는 처음 설명은 틀렸고 문서에는 실제 동작을 적었다 (ADR-013, .env.example).
- 구현 중 테스트로 잡은 버그 2건: 로그인 IP 필터가 `getServletPath()`로 경로를 비교해 MockMvc에서 동작하지 않음 → 요청 URI로 비교. 비밀번호 변경 화면에서 실패 기록이 롤백돼 무제한 대입 가능 → `recordFailure`를 `REQUIRES_NEW`로 (ADR-012).
- 8b(이메일 변경)는 커밋 `f69410b` 하나에 모았다. 빼야 하면 이 커밋만 되돌린다 (공통 재인증 `CurrentPasswordVerifier`도 같이 되돌아가며 8a는 원래 코드로 돌아간다).
- 로컬 `.env`의 한글 주석은 M0에서 ASCII 인코딩으로 저장해 깨져 있다(값에는 영향 없음). 필요하면 `.env.example`을 다시 복사해 값을 옮긴다.
- 확인 완료: PR #3으로 main 병합.

### M1-c에서 확정한 결정 (2026-10-17)
1. **재가입(B안)**: 탈퇴 후 30일 유예 중에도 같은 이메일·카카오 계정으로 새 계정을 만들 수 있다. unique는 ACTIVE 계정끼리만 적용한다. 탈퇴 복구는 지원하지 않는다. 이메일·kakao_id 조회 메서드는 상태 조건을 받아야 한다(`LandlordRepositoryConventionTest`).
2. **카카오 계정 탈퇴 재인증**: POST로 의사를 확인한 뒤 10분 안에 카카오 재로그인(`prompt=login`, 링크는 GET). 콜백에서 같은 계정이면 바로 탈퇴한다(결정 12).
3. **연결 끊기**: 서비스 앱 어드민 키(`KAKAO_ADMIN_KEY`). 운영 필수이고, 없으면 기동하지 않는다.
4. **카카오 연결 해제 웹훅**: M6로 미룬다(위 "출시 전 필수").
5. **카카오 이메일**: `is_email_valid && is_email_verified`일 때만 인증된 것으로 저장한다. 그 밖에는 우리 인증 메일을 보낸다. → 지금은 이메일 scope를 요청하지 않아 동작하지 않는다(아래 "M1-c 브라우저 확인 중 변경").
6. **닉네임**: 이름 기본값으로만 쓰고 수정할 수 있다. 없으면 직접 입력한다.
7. **알림 이메일 "나중에 하기"**: 허용하고 안내 띠로 알린다.
8. **consent_log**: `agreed_at`만 둔다. 파기 때 함께 지운다. 법적 보관 의무는 전문가 검토 항목(ADR-016).
9. 약관 버전 변경 시 **재동의는 범위 밖**이다.
10. 카카오 키가 없으면 local·CI는 카카오 로그인을 끈다(버튼 숨김). 운영은 필수.
11. 카카오 계정의 **인증된** 알림 이메일 변경은 P1이다. 미인증 주소 고치기는 지금 제공한다.
12. 카카오 계정 탈퇴는 카카오 확인 콜백에서 바로 처리한다.
- **PKCE**: Security 7.1.1 기본값대로 켠다. 계획 단계 설명이 틀렸던 경위와 대응책은 ADR-014에 있다.
- **연결 끊기 실패(C안, 분리 파기)**:
  - 30일이 되면 이름·이메일 등은 지우고, 회원번호만 `kakao_unlink_pending`(V11, FK 없음, 저장 항목 5개)에 남겨 하루 한 번 상한 없이 재시도한다.
  - 같은 회원번호로 사용 중인 계정이 있으면 끊지 않는다.
  - 알림: 설정 오류·거부는 첫 실패, 일시 장애는 연속 3회, 탈퇴 후 60일이면 심각. 하루 한 줄로, 해결될 때까지 매일 남긴다.
  - 400 + 카카오 코드 -101(앱과 연결되지 않은 사용자)은 "이미 끊김"으로 보고 성공으로 처리한다 (아래 "M1-c 확인된 것").
  - 자세한 내용은 ADR-015 결정 8~15.

### M1-c 브라우저 확인 중 변경 (2026-10-17)
- 실제 카카오 로그인에서 **KOE205(invalid_scope)**가 났다. 원인: 카카오 콘솔의 이메일 동의항목(`account_email`)이 "권한 없음"이다(개인 개발자 앱이라 비즈 앱 전환이 필요). 닉네임(`profile_nickname`)만 선택 동의로 설정돼 있다.
- **결정**: scope는 `profile_nickname`만 요청한다(`app.kakao.scopes`). 카카오에서 이메일이 오지 않는 것을 기본 경로로 삼는다. 가입 단계에서 알림 이메일을 직접 입력받고("나중에 하기" 유지), 우리 인증 메일로 확인한다.
- "카카오가 인증한 이메일이면 바로 인증" 분기(M1-c 결정 5)는 코드에 남기되, 이메일 scope를 요청하지 않으면 동작하지 않는다(테스트로 확인). 비즈 앱 전환 뒤 다시 쓸지는 위 "배포 후 검토"에서 정한다.

### M1-c 확인된 것 (2026-10-17, 개발자가 실제 카카오 계정·로컬 DB로 확인)
계획 단계에서 "확인하지 못한 것"이던 항목은 모두 확인됐다. 남은 "확인할 것"은 없다.
- [x] **PKCE**: 이전에는 카카오가 지원하는지 문서로 확인하지 못했다. Security 7.1.1 기본값대로 `code_challenge`/`code_verifier`를 보내도 실제 카카오 로그인·가입·탈퇴가 모두 성공했다. 끌 필요가 없다 (ADR-014).
- [x] **재가입·재연결 시 회원번호**: 이전에는 확인하지 못했다. 탈퇴 후 같은 카카오 계정으로 재가입해도 회원번호가 같았다(계정 2개, 회원번호 1개). 연결을 끊었다가 다시 연결해도 번호가 유지된다. 그래서 ADR-015 결정 10(사용 중 계정 보호)과 회원번호 PK 설계의 전제가 맞다.
- [x] **이미 끊긴 회원을 다시 끊을 때의 응답**(검증 3): `status=400, kakaoCode=-101`이 왔다. 카카오 문서에서 -101은 "해당 앱에 카카오계정 연결이 완료되지 않은 사용자가 호출한 경우"다. **결정**: 이 응답은 "이미 끊김"으로 보고 성공으로 처리한다. 대기 행을 지우고, 같은 회원번호의 탈퇴 행에 `kakao_unlinked_at`을 채우고, 알림은 울리지 않는다. 다른 4xx는 그대로 REJECTED다. 이미 끊긴 경우와 연결된 적 없는 회원번호는 구분하지 못한다(ADR-015 결정 14).
- [x] **탈퇴 즉시 연결 끊기**: 성공했고, 대기 행은 0이었다. 탈퇴 후 같은 카카오 계정으로 재가입(B안)도 동작했다.
- [x] **30일 뒤 파기**(검증 4): 두 계정 모두 지워졌고, 연결 데이터(동의 기록 포함)도 모두 삭제됐다. 대기 행은 생기지 않았다.
- 확인 중 수정: 카카오 scope(이메일 동의항목 제외, 위 "M1-c 브라우저 확인 중 변경"), -101 처리(V12에서 COMMENT만 갱신).

### M2 범위 (PRD 9장, 4.2, 4.3)

### M2에서 확정한 결정 (2026-10-17 승인)
1. **호실 상태 4가지**: 공실 / 입주중 / 입주 예정 / 기간 지남. 저장하지 않고 계약에서 계산한다. "기간 지남" ACTIVE 계약과 새 ACTIVE 계약이 함께 있을 때의 "현재 계약" 정의는 ADR-019에 적고 테스트한다.
2. **기간 경계 `[)`**: 종료일 당일 이어서 입주할 수 있다. EXCLUDE 범위식은 `daterange(start_date, end_date, '[)')`. 화면 표기는 시작일 = "들어오는 날", 종료일 = "나가는 날". PRD의 `'[]'`에서 바꾼 이유는 ADR-019.
3. **실제 종료일(`ended_on`)**: 시작일 이후 ~ 오늘까지. 예정 퇴거는 종료일(end_date) 단축으로 처리한다.
4. **월세 변경**: 적용월은 이번 달 이후이고 계약 기간 안. 아직 시작하지 않은 미래 변경은 교체·취소할 수 있고, 이미 시작된 변경은 수정할 수 없다. 최초 행(시작월)은 계약 수정으로만 정정한다.
5. **금액 기준**: lease에는 금액 컬럼을 두지 않는다. `lease_rent_history`만 기준이다.
6. **연락처 중복**: 임대인 안에서 unique. 같은 번호면 "이미 등록된 세입자로 계약할까요?"로 기존 세입자를 다시 쓴다.
7. **연락처 형식**: 휴대폰(01X)만.
8. **금액 상한**: 보증금 100억 원, 월세·관리비 1억 원(PRD).
9. **암호화 대상**: 세입자 이름·연락처·메모, 계약의 계좌번호·예금주. 건물·호실·계약 메모는 평문이고, 입력칸 아래에 "주민번호·계좌번호는 적지 마세요"를 안내한다.
10. **키**: `APP_ENCRYPTION_KEY`, `APP_ENCRYPTION_KEY_VERSION`, `APP_HMAC_KEY`(PRD) + `APP_ENCRYPTION_PREVIOUS_KEYS`(복호화 전용). local도 키 필수다(없으면 기동 실패, 임시 키 금지).
11. **삭제**: 건물은 호실이 없을 때만, 호실은 계약 기록이 없을 때만 지울 수 있다. 계약은 수정으로 정정하고, 삭제는 "청구가 없을 때만" 허용한다(M2에는 청구가 없어 항상 가능).
12. **계약 수정 범위**: 세입자 정보, 보증금, 납부일, 종료일(연장·단축, 겹침 재검사), 계좌, 메모. 호실과 시작일은 수정할 수 없다.
13. **HTMX**: M2에서 도입하지 않는다. 삭제·종료는 확인 화면(GET 확인 → POST 실행)으로 한다.
14. **임대인 연락처(`landlord.phone_enc`, SET-1)**: M2에서 빼고 M5로 미룬다.
15. **Money**: A안(`long` 유지). M3 시작 때 다시 검토한다(ADR-003).
16. **QueryDSL**: 보류한다. M3 청구 목록에서 다시 판단한다.
17. **호실 유형**: 원룸·투룸·쓰리룸 이상·상가·사무실·기타.
18. `issue_days_before`는 M3, `notify_opt_out`은 M4에서 추가한다.
19. **세입자 정보 보관 기간**: 미정으로 두고 삭제 기능은 만들지 않는다(위 "출시 전 전문가 검토").
20. **입금 계좌**: 계약마다 필수. 같은 임대인(landlord_id로 한정)의 직전 계약 계좌로 미리 채운다.
21. **건물 이름**: 같은 임대인 안에서 중복 불가. `UNIQUE(landlord_id, name)` + 친절한 안내.
- 계획에서 정한 것: 복합 FK(`(부모_id, landlord_id)`)로 다른 임대인 연결을 DB에서 차단, 리포지토리는 `findById`가 없는 형태로 모든 조회에 landlordId 필수, 계약 등록은 한 화면 4구역 + 확인 화면(세션에 평문을 저장하지 않으려고), 새 테이블은 모두 landlord CASCADE라 지금 파기 배치로 함께 지워진다(모듈별 Purger 불필요, 테스트로 확인).
- 진행 방식: V13·V14는 파일을 만든 뒤 **커밋 전에 SQL 전문을 개발자에게 보여 주고 확인을 받는다.** Hibernate 7 AttributeConverter에 Spring 빈 주입이 안 되면 멈추고 알린다.

## 기타 메모
- 포매터는 Eclipse 기본 프로필로 시작했다. 개발자의 Eclipse 포매터 XML을 받으면 `config/formatter/eclipse-formatter.xml`을 교체하고 `.\gradlew.bat spotlessApply`로 일괄 재포맷한다 (재포맷은 별도 커밋 `style:`).
  Eclipse의 Organize Imports 순서도 함께 내보내(`.importorder`) Spotless `importOrderFile(...)`로 맞추면 저장 시 import 순서가 흔들리지 않는다. 현재는 `java, javax, org, com, 기타` 순서로 임시 지정했다.
- Spotless의 Eclipse JDT 버전은 개발자 Eclipse(2025-06 = 4.36)에 맞춰 `eclipse("4.36")`으로 고정했다. Eclipse를 업그레이드하면 이 값도 함께 올린다.
- Gradle 9.8.1은 2주 규칙의 예외로 채택했다 (ADR-004).
- PowerShell 5.1에서 한글 커밋 메시지는 `-m`으로 넘기면 깨질 수 있다. UTF-8 파일로 만들어 `git commit -F <파일>`로 커밋한다.
- 커밋하지 않을 임시 파일이 working tree에 있을 때는 `git add -A` 대신 파일을 지정해서 올린다.
