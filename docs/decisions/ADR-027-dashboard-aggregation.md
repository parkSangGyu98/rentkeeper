# ADR-027: 임대인 대시보드 집계

- 상태: 승인됨 (M4 커밋 4, M4 결정 14·16)
- 날짜: 2026-10-24

## 맥락
- 로그인한 임대인이 처음 보는 화면에서 처리할 일(세입자 신고), 이번 달 돈, 납부일 지남, 곧 끝나는 계약, 공실을 한 번에 본다(PRD 4.6 DASH-1~4).
- PRD 8.3: 대시보드 p95 500ms. MVP는 쿼리 직접 집계 + 인덱스로 하고, 느리면 측정한 뒤 비정규화·캐시를 정한다.
- 대시보드는 property·lease·billing 세 모듈의 정보를 모은다. 다른 모듈의 엔티티·리포지토리는 쓰지 않는다(ADR-020).

## 결정
- **모듈**: `dashboard`(맨 위). property·lease·billing의 서비스만 쓴다. 로그인 정보는 `auth.security`만, 세입자 화면(`tenantlink`)과는 서로 기대지 않는다(ArchUnit). `/app`과 `/app/dashboard`가 같은 화면이다.
- **구역** (위에서부터)
  1. 확인 기다리는 입금 신고: TENANT_REPORTED(모든 달), 먼저 알린 것부터. "N번째 신고"는 상태 이력에서 → TENANT_REPORTED로 바뀐 횟수다.
  2. 이번 달 받을 돈·받은 돈·남은 돈: 받을 월세 목록과 같은 규칙(취소 제외, 남은 돈은 청구마다 0 아래로 내려가지 않게).
  3. 납부일 지남: OVERDUE(모든 달), 오래 지난 것부터, 남은 돈 합계.
  4. 90일 안에 끝나는 계약: 진행 중이고 나가는 날 ≤ 오늘 + 90일. 나가는 날이 이미 지났는데 종료하지 않은 계약도 넣는다("계약 종료가 필요해요"). 90일은 PRD NOTI-5(D-90)와 같다.
  5. 공실: 기존 호실 상태 규칙(`UnitOccupancyRule`)으로 센다.
- **집계 방식**
  - 합계·건수는 DB가 센다(`ChargeRepository.monthTotals`·`statusTotals`, JPQL 집계).
  - 목록은 구역마다 앞의 10건만 읽고(`Limit`), 그 행의 이름만 복호화한다. 나머지는 건수로만 보이고, 받을 월세 목록의 칸에서 본다.
- **건물 고르기**: GET `?propertyId=`. 그 건물 호실의 계약 ID(종료 포함)로 집계를 한정한다(`… and c.leaseId in :leaseIds`). 남의 건물은 `PropertyService.detail`이 404를 낸다. 숫자가 아닌 값도 404다.
- **인덱스**: 새로 만들지 않았다. 기존 `ix_charge_landlord_month_status`(이번 달)와 `ix_charge_status_due_date`(상태별)로 충분했다(아래 측정).

## 측정 (개발 PC, Testcontainers, `gradlew perfTest`, `DashboardThroughputTests`)
- 데이터: 임대인 1명, 건물 20개 × 호실 1,000개 = 계약 2만 건. 지난 12개월 + 이번 달 청구 26만 건(납부일 지남 7,272건, 세입자 신고 1,000건).
- 서비스 호출 p95 (30회):
  - 모든 건물 **432ms**, 건물 하나(1,000호실) **485ms**.
  - 처음 구현에서는 건물 하나가 **763ms**로 목표를 넘었다. SQL은 모두 몇 ms였다(납부일 지남 합계 4ms, 이번 달 건수 2ms, 목록 0.3ms).
  - 원인은 건물 고르기 칸을 채우려고 호실 2만 개 전체의 공실 상태를 계산한 것이었다. 고르기 칸은 이름만 읽고(`PropertyService.options`), 공실은 고른 건물의 호실 상태로만 세게 고쳤다.
- 이 값은 서비스 호출만 잰 것이다(화면 그리기·HTTP 제외). 남은 시간의 대부분은 호실·계약을 읽어 공실 상태를 계산하는 데 쓴다.

## 결과
- 보통 임대인(호실 수십 개)은 문제가 없다. 호실 2만 개의 극단적인 경우에도 목표 안이지만 여유가 적다.
- 느려지면 먼저 할 일: 공실 수를 DB 집계로 바꾸기(호실·계약을 엔티티로 다 읽지 않기). 그다음이 캐시다. 운영에서 실제 응답 시간을 본 뒤 정한다(M6 관측성).
- 세입자가 허위로 신고하면 납부일 지남 전환이 멈춘다(M3 결정 7). 그래서 신고를 맨 위에 두어 임대인이 바로 처리하게 했다.
