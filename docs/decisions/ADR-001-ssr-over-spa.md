# ADR-001: 화면은 SSR(Thymeleaf + HTMX)로 만든다

- 상태: 승인됨
- 날짜: 2026-10-17

## 맥락
- 개발자는 1인 백엔드(Java/Spring) 개발자이고, 운영·유지보수도 혼자 한다.
- 주 사용자(임대인)는 40~60대, IT 숙련도가 낮고 모바일 웹과 PC를 함께 쓴다. 화면은 폼·목록·요약 카드 중심이다.
- 세입자는 가입 없이 토큰 링크 한 장으로 청구서를 본다. 첫 화면이 빨리 떠야 하고, 검색엔진 차단(`noindex`)·`Referrer-Policy` 같은 헤더 제어가 쉬워야 한다.

## 결정
Spring MVC + Thymeleaf로 서버에서 HTML을 렌더링하고, 부분 갱신이 필요한 곳(입금 확인 토글, 목록 필터, 폼 부분 검증)만 HTMX를 쓴다. 스타일은 Tailwind CSS(standalone CLI, Node 불필요)로 한다.

## 검토한 대안
| 대안 | 장점 | 채택하지 않은 이유 |
|---|---|---|
| React/Next.js SPA + REST API | 풍부한 상호작용, 프런트 생태계 | 프로젝트·배포 단위가 2개, 인증(CORS/토큰) 복잡도 증가, 1인 유지보수 부담 |
| Vue + Spring REST | 학습 곡선 낮음 | 위와 같은 이유 |
| Thymeleaf만 (HTMX 없음) | 가장 단순 | 토글·필터마다 전체 새로고침 → 저숙련 사용자 경험 저하 |

## 결과
- 좋아지는 점: 코드베이스·배포 단위 하나, 세션 기반 인증과 CSRF를 Spring Security 기본값으로 처리, 디버깅이 서버 로그 하나로 끝남.
- 감수할 점: 복잡한 클라이언트 상호작용에는 불리하다. 화면 요구가 커지면 그때 재검토한다.
- 확장 경로: 앱·외부 연동이 필요해지면 서비스 계층은 그대로 두고 `/api/v1` REST 컨트롤러만 추가한다. 이를 위해 컨트롤러에 비즈니스 로직을 두지 않는다(PRD 10장 계층 규칙).
