# ADR-015: 회원 탈퇴와 재인증·카카오 연결 끊기

- 상태: 승인됨 (연결 끊기 실패 처리는 2026-10-17 C안으로 결정, 아래 "파기와 연결 끊기 재시도")
- 날짜: 2026-10-17

## 맥락
- PRD AUTH-5: 회원 탈퇴 시 즉시 로그인 차단, 개인정보는 30일 뒤 파기.
- 카카오 공식 문서: 서비스 탈퇴 시 카카오 연결 끊기(unlink)를 **반드시** 호출해야 한다. 회원번호(user_id)도 지워야 할 개인정보다.
- 우리는 카카오 액세스 토큰을 보관하지 않는다(ADR-014). 탈퇴 시점에도, 실패 후 다시 시도할 때도 토큰 없이 끊을 수 있어야 한다.
- M1-c 결정 1(B안): 유예 중에도 같은 이메일·카카오 계정으로 새로 가입할 수 있고, 탈퇴 복구는 지원하지 않는다(V9).

## 결정
1. **상태 전이**: `Landlord.withdraw(now)`로만 `ACTIVE → WITHDRAWN`, `withdrawn_at` 기록. 되돌리는 전이는 없다. 이미 탈퇴한 계정을 다시 탈퇴하면 예외.
2. **재인증**(민감 작업)
   - 이메일 가입 계정: 지금 비밀번호 + 확인 체크. 틀리면 로그인 실패 횟수에 더한다(ADR-012). 잠기면 15분 대기.
   - 카카오 계정(M1-c 결정 2·12): 확인 체크를 POST로 받으면 세션에 "탈퇴 의사 확인"(`KakaoWithdrawalIntent`: landlord id + 만료 10분)을 저장하고, 카카오 재로그인 **링크(GET)** 를 보여 준다(CSP form-action 때문에 카카오 주소로 폼을 보낼 수 없다, ADR-014). 이 세션의 인가 요청에는 `prompt=login`을 붙여 카카오에 로그인돼 있어도 다시 입력하게 한다.
   - 카카오 콜백에서 의사 확인을 꺼내(한 번만 사용):
     - 같은 계정 + 10분 안 → 바로 탈퇴, 로그아웃, `/withdrawn`
     - 같은 계정 + 10분 지남 → 탈퇴하지 않고 탈퇴 화면(`?expired`)
     - 다른 카카오 계정 → 탈퇴하지 않는다. 로그인 상태가 그 계정으로 바뀌었으므로 로그아웃시키고 `/login?withdrawMismatch`
     - 카카오에서 취소·실패 → 탈퇴 화면(`?kakaoError`), 원래 로그인은 그대로
   - 의사 확인이 없는 보통 카카오 로그인에는 `prompt`를 붙이지 않고 탈퇴도 하지 않는다.
   - 카카오톡 인앱 브라우저는 `prompt=login`을 지원하지 않는다(카카오 문서). User-Agent에 `KAKAOTALK`이 있으면 "다른 브라우저로 열기" 안내를 보여 준다.
3. **즉시 차단**(한 트랜잭션): 탈퇴 상태로 변경 → 모든 기기의 세션과 remember-me 토큰 삭제(`AccountSessionTerminator`) → 메일 링크(account_token)·로그인 실패 기록 삭제 → 지금 기기 로그아웃(세션 무효화, remember-me 쿠키 삭제). 이메일·카카오 로그인과 remember-me 조회는 ACTIVE만 찾으므로 바로 로그인할 수 없다.
4. **안내 메일**: 인증된 이메일이 있을 때만, 커밋 뒤에 보낸다(M1-b 결정: 알림은 인증된 주소로만).
5. **카카오 연결 끊기**: 서비스 앱 어드민 키 방식(`POST /v1/user/unlink`, `Authorization: KakaoAK {어드민 키}`, `target_id_type=user_id`, `target_id={회원번호}`).
   - 탈퇴 트랜잭션이 **커밋된 뒤** 호출한다. 카카오 응답을 기다리는 동안 DB 연결을 잡지 않고, 카카오가 실패해도 탈퇴를 되돌리지 않는다.
   - 성공하면 같은 회원번호의 탈퇴 계정 행 **모두**에 `landlord.kakao_unlinked_at`(V10)을 채운다. 실패하면 대기 행(`kakao_unlink_pending`, V11)을 만들고 파기 배치가 다시 시도한다. 기록은 새 트랜잭션으로 한다(커밋 직후 콜백에서 기존 트랜잭션에 참여하면 커밋되지 않는다).
   - 어드민 키와 회원번호는 로그에 남기지 않는다(landlord id와 예외 종류만).
6. **V10 제약** `ck_landlord_kakao_unlinked`: `kakao_unlinked_at`은 탈퇴한 카카오 계정에만 있을 수 있다. 이메일(LOCAL) 계정과 사용 중인 계정은 항상 NULL.
7. 카카오 계정은 비밀번호가 없으므로 비밀번호 탈퇴 요청은 404, 이메일 계정의 카카오 탈퇴 요청도 404.

## 검토한 대안
| 대안 | 채택하지 않은 이유 |
|---|---|
| 카카오 계정도 확인 체크만으로 탈퇴 | 세션을 가로챈 사람이 바로 탈퇴시킬 수 있다(결정 2) |
| 액세스 토큰으로 연결 끊기 | 토큰을 보관해야 한다(ADR-014와 충돌). 실패 후 다시 시도할 수 없다 |
| 연결 끊기 성공 여부를 기록하지 않고 파기 때마다 다시 호출 | 이미 끊긴 회원을 다시 끊을 때의 카카오 응답을 확인하지 못했다. 잘못 판단하면 계정이 영원히 파기되지 않는다 |
| 탈퇴 트랜잭션 안에서 연결 끊기 | 외부 호출 동안 DB 연결을 잡고, 카카오 장애가 탈퇴 자체를 막는다 |

## 파기와 연결 끊기 재시도 (2026-10-17 결정: C안, 분리 파기)
카카오 장애나 어드민 키 오류로 연결 끊기가 계속 실패하는 계정이 생길 수 있다. 파기를 미루면 30일 파기 약속을 어기고, 그냥 지우면 회원번호를 잃어 끊을 방법이 없어진다(카카오 정책 위반). 그래서 30일이 되면 이름·이메일 등은 예정대로 지우고, **연결 끊기에 꼭 필요한 회원번호만** 대기 테이블에 남겨 끊길 때까지 재시도한다.

8. **`kakao_unlink_pending`(V11)**: `kakao_id`(PK), `withdrawn_at`, `failure_count`, `last_failed_at`, `last_failure_type`(CONFIG/TRANSIENT/REJECTED). 저장 항목은 이 다섯 개뿐이고, 이메일·이름·landlord id는 저장하지 않는다.
   - landlord에 **FK를 걸지 않는다.** landlord가 지워진 뒤에도 남아야 하고, 참조할 landlord id도 없다.
   - 같은 회원번호는 한 행(PK)이다. 탈퇴-재가입-탈퇴로 다시 들어오면 upsert로 합치고, 탈퇴 시각은 더 이른 값을 유지한다(60일 판정이 늦어지지 않게).
   - 공통 컬럼(`created_at`/`updated_at`)은 두지 않는다(consent_log와 같은 예외). `withdrawn_at`·`last_failed_at`이 그 역할을 한다.
9. **역할 나누기**: "끊기가 남아 있다" = 대기 행이 있다. 재시도 대상은 대기 테이블로만 고른다. `kakao_unlinked_at`은 그 탈퇴 건이 끝났다는 기록일 뿐이다(V11에서 COMMENT를 다시 붙임).
   | 상황 | `kakao_unlinked_at` | 대기 행 |
   |---|---|---|
   | 탈퇴 즉시 끊기 성공 | 시각 | 없음 |
   | 탈퇴 즉시 끊기 실패 | NULL | 그 자리에서 생성 |
   | 재시도 성공 | 같은 회원번호의 탈퇴 행 모두 채움 | 삭제 |
   | 파기 시점에 NULL | landlord째 삭제 | 있도록 보장(upsert)한 뒤 삭제 |
10. **사용 중인 계정 보호**: 같은 회원번호의 ACTIVE 카카오 계정이 있으면 끊지 않는다. 대기 행을 지우고, 파기 때도 대기 행을 만들지 않는다. 사용자가 다시 동의해 쓰고 있는 연결이라, 옛 탈퇴 건 때문에 사용 중인 계정을 깨면 안 된다. 재연결 때 회원번호가 그대로인지는 확인하지 못했다(바뀌면 그 계정에 로그인할 수 없게 될 수 있다).
11. **파기 배치**(`WithdrawnAccountPurger`, 매일 03:30 서울): 파기 → 재시도 → 알림 순서.
    - **파기**: 대상은 `WITHDRAWN`이고 탈퇴 후 30일이 지난 계정. 계정마다 별도 트랜잭션(`REQUIRES_NEW`)으로 처리하고 각각 try/catch로 감싼다. 한 계정이 실패하면 그 계정만 롤백하고 ERROR 로그(landlord id만)를 남긴 뒤 다음 계정으로 넘어간다.
      - 트랜잭션 안에서 할 일: `FOR UPDATE`로 다시 확인 → (끊기가 남은 카카오 계정이면) 대기 행 upsert → `spring_session`·`persistent_logins` 삭제 → landlord 삭제. account_token·login_failure·consent_log는 CASCADE로 함께 지워진다.
      - **대기 행 생성과 landlord 삭제는 같은 트랜잭션이다.** 그래서 회원번호를 잃는 상태가 생길 수 없다.
    - **재시도**: 대기 행마다 카카오를 트랜잭션 밖에서 호출하고 결과를 짧은 트랜잭션으로 기록한다. 하루 한 번, 상한은 없다.
    - **중간에 멈추면** 진행 중이던 계정의 트랜잭션만 롤백되고, 다음 실행에서 다시 처리된다. **두 번 돌아도** 결과가 같다(지운 계정은 대상이 아니고 upsert는 한 행).
    - **landlord를 참조하는 새 테이블은 ON DELETE CASCADE로 만든다.** 빠뜨리면 이 배치가 그 계정을 지우지 못한다(`WithdrawnAccountPurgeTests`가 모든 FK를 검사).
12. **실패 분류**: 401/403·어드민 키 없음 = `CONFIG`, 5xx·429·시간 초과·연결 실패 = `TRANSIENT`, 그 밖의 4xx = `REJECTED`. 실패 로그에는 HTTP 상태와 카카오 에러 응답의 숫자 `code`만 남긴다(`status=400 kakaoCode=-101` 형태). 응답 본문 전체와 `msg`는 남기지 않는다.
13. **운영자 알림**(`OpsAlertNotifier`, 정해진 문구 `KAKAO_UNLINK_ALERT`, 로거 `rentkeeper.ops-alert`): 회원번호·이메일·이름은 넣지 않고 건수와 종류만 넣는다.
    - 설정 오류는 첫 실패에 바로 알린다. 탈퇴 직후 실패도 배치를 기다리지 않는다.
    - 일시 장애는 연속 3회부터, 거부(REJECTED)는 첫 실패부터 알린다.
    - 탈퇴 후 60일이 지나도 못 끊으면 "심각"으로 알린다.
    - 배치 끝에 남은 대기 행으로 판정해 **하루 한 줄**로 묶어 남긴다. 해결될 때까지 매일 다시 남긴다.
    - 지금은 ERROR 로그만 남긴다. 운영자 메일(`OPS_ALERT_EMAIL`, 하루 한 통)은 운영 메일 발송이 생기는 M5에서 이 인터페이스의 구현으로 추가한다.
14. **이미 끊긴 회원을 다시 끊는 경우**: 연결 끊기는 성공했는데 그 기록이 실패하면, 다음 날 이미 끊긴 회원을 다시 호출하게 된다. 이 응답은 일단 실패(대개 REJECTED)로 기록하고 알린다. 실제 응답 코드는 개발자가 실제 카카오 테스트 계정으로 확인한 뒤 "이미 끊김"으로 볼지 정한다. **추측으로 처리하지 않는다.**
15. **수동 실행**(브라우저 확인용): local 프로필에서 `--app.purge.run-on-startup=true`를 줄 때만 앱 시작 시 한 번 돈다(`LocalPurgeRunner`). HTTP 경로는 없고, prod에는 이 빈이 없다(테스트로 확인).

### 운영 절차 후보 (M6 `docs/runbook.md`로 옮김)
**REJECTED로 계속 실패하는 대기 행 정리.** "이미 끊김" 판정 기준은 개발자가 실제 응답을 확인한 뒤 정한다. 그 전에는 아래를 수동으로 한다.
1. 알림 로그(`KAKAO_UNLINK_ALERT ... rejected=N`)와 앱 로그의 `kakao unlink failed: status=... kakaoCode=...`로 응답을 확인한다.
2. DB에서 오래 실패한 행을 본다. 회원번호는 화면에 띄우지 않고 건수와 시각만 본다.
   ```sql
   SELECT withdrawn_at, failure_count, last_failed_at, last_failure_type
   FROM kakao_unlink_pending WHERE last_failure_type = 'REJECTED' ORDER BY withdrawn_at;
   ```
3. 카카오 디벨로퍼스 콘솔(또는 사용자 관리 도구)에서 그 회원의 연결 상태를 확인한다. 회원번호는 DB 안에서 복사해 쓰고 채팅·문서에 남기지 않는다.
4. 연결이 이미 끊겨 있으면 그 행을 지운다.
   ```sql
   DELETE FROM kakao_unlink_pending
   WHERE last_failure_type = 'REJECTED' AND withdrawn_at = '<2에서 본 탈퇴 시각>';
   ```
5. 연결이 남아 있으면 지우지 않는다. 원인(키·IP·앱 설정)을 고치고 다음 배치를 기다린다.

## 결과
- 탈퇴하면 그 순간부터 어떤 기기·방법으로도 로그인할 수 없고, 같은 이메일·카카오 계정으로 새로 가입할 수 있다.
- 30일 뒤 이름·이메일 등 개인정보는 행째 지워진다. 끊지 못한 카카오 회원번호만 대기 테이블에 남고, 끊으면 바로 지운다.
- **출시 전 전문가 검토 항목**: 탈퇴 후 30일이 지나 카카오 회원번호를 대기 테이블에 보관하는 것이 적법한지와 보관 기간(끊기 성공 즉시 삭제). 카카오 문서는 탈퇴 시 연결 끊기를 반드시 하라고 하면서 user_id도 파기 대상 개인정보라고 한다. 이 둘을 어떻게 맞출지가 쟁점이다.
