# ADR-031: 공개 주소의 접근 제어 — 초대 코드 가입과 방문자별 임시 데모

- 상태: 승인됨 (M6 커밋 3·4, M6 결정 3과 개발자 보강 1~4)
- 날짜: 2026-10-24

## 맥락
- 배포 주소는 공개된다. 낯선 사람이 가입해 실제 세입자 이름·연락처·계좌를 넣으면, 법률 검토 없이 남의 개인정보를 맡게 된다.
- 반대로 포트폴리오로 쓰려면 면접관이 가입 없이 바로 써 볼 수 있어야 한다.

## 결정
- **일반 가입은 초대 코드가 있어야 한다** (`InviteCodeGate`, 커밋 3)
  - 이메일 가입과 카카오 첫 가입 모두. 코드가 틀리면 계정을 만들지 않고 이메일 중복 같은 다른 확인도 하지 않는다(코드 없이 계정 존재를 캐지 못하게).
  - 비교는 두 값의 SHA-256을 `MessageDigest.isEqual`로 한다(일정 시간 비교, 길이도 드러내지 않음). 원문은 메모리에 두지 않는다.
  - 시도는 IP당 1시간 10회(`INVITE_CODE_PER_IP`, ADR-012). 설정이 비면 제한이 없고(local·테스트), prod는 16자 이상이 없으면 기동하지 않는다.
- **방문자는 임시 데모 계정을 쓴다** (`demo` 모듈, V22 `landlord.demo_expires_at`, 커밋 4)
  - 첫 화면 [데모로 둘러보기] → 방문자마다 임대인 계정을 하나 만들고 가짜 데이터를 넣어 바로 로그인한다. 24시간 뒤 매시 20분 정리 배치가 계정과 데이터(CASCADE), 세션을 지운다.
  - 가짜 데이터는 실제 서비스 코드로 만든다: 건물 2·호실 6·계약 4, 다 받음·세입자 신고·일부 받음 뒤 납부일 지남·곧 끝나는 계약. 화면에서 하는 것과 같은 상태와 이력이 남는다.
  - 일반 계정과 같은 테이블이라 소유권 검증(ADR-018)을 그대로 쓴다. 데모끼리도 서로의 데이터를 볼 수 없다(테스트).
  - 모든 화면 맨 위에 "데모입니다. 실제 정보를 입력하지 마세요. …에 모두 지워져요" 띠.
- **보강(개발자)**
  1. 동시에 있는 데모 계정 상한(기본 50, `APP_DEMO_MAX_ACCOUNTS`). Postgres advisory lock으로 세고 만드는 사이를 한 줄로 세워, 동시에 눌러도 넘지 않는다. 꽉 차면 503 안내. IP당 1시간 5회(`DEMO_START_PER_IP`).
  2. 초대 코드 시도 횟수 제한과 일정 시간 비교(위).
  3. 데모 계정은 비밀번호·이메일·알림 받을 이메일 바꾸기, 탈퇴, 인증 메일 다시 받기를 할 수 없다(설정 화면으로 돌려보냄, `DemoRestrictionInterceptor`). 세입자 안내 문자는 켤 수 없다(보내도 꺼진 채 저장). 이메일은 인증하지 않은 가짜 주소(`…@demo.invalid`)라 어떤 메일도 받지 않는다.
  4. 시작 화면에 101호 세입자 링크를 한 번 보여 준다(`no-store`, 저장하지 않음). 계약 화면에서 새로 만들 수도 있다.
- 비밀번호는 아무도 모르는 값의 해시라 데모 계정에 비밀번호로는 로그인할 수 없다.

## 검토한 대안
| 대안 | 채택하지 않은 이유 |
|---|---|
| 초대 코드만 | 면접관이 바로 써 볼 수 없다 |
| 공용 데모 계정 하나 | 방문자끼리 입력이 보이고 데이터가 엉망이 된다. 누군가 실제 정보를 넣으면 다른 방문자에게 보인다 |
| 데모를 별도 DB·도메인으로 | 서버 한 대·포트폴리오 규모에 비해 무겁다. 실서비스 전환 때 다시 본다("실서비스 전환 시 볼 목록") |

## 결과
- 데모를 만들 때 BCrypt 한 번과 서비스 호출 여러 개를 거쳐 시작이 조금 느리다(시간은 재지 않았다. 배포 뒤 확인).
- 데모 데이터를 넣다 실패하면 빈 데모 계정이 남을 수 있지만, 만료되면 함께 지워진다.
- 실제 사용자를 받으려면 가입 공개, 데모 분리, 약관·처리방침 확정이 함께 필요하다(실서비스 전환 시 볼 목록).
