# ADR-016: 약관·개인정보처리방침 동의 기록

- 상태: 승인됨
- 날짜: 2026-10-17

## 맥락
- PRD AUTH-6: 약관/개인정보 동의를 `consent_log`에 버전·시각과 함께 저장한다.
- M1-a부터 가입 폼에서 필수 동의 체크를 검증만 하고 기록은 하지 않았다(M1-c로 미룸).
- 카카오 가입(M1-c)도 같은 동의를 받아야 한다.
- 약관과 처리방침은 아직 초안(v0.1)이고, 출시 전 전문가 검토를 받는다.

## 결정
1. `consent_log(id, landlord_id, document_type, document_version, agreed_at)`(V8).
   - `document_type`: `TERMS`(이용약관), `PRIVACY`(개인정보처리방침). CHECK 제약으로 제한한다.
   - `document_version`: 앱의 `LegalDocument`에 정의된 그 시점 버전(지금 v0.1).
   - `agreed_at`: 동의 시각(UTC, 주입된 Clock).
2. **수정하지 않는 기록**이므로 PRD의 공통 컬럼(`created_at`/`updated_at`) 대신 `agreed_at`만 둔다(공통 규칙의 예외).
3. 가입할 때 두 문서에 대한 동의를 **계정 생성과 같은 트랜잭션**에서 두 행으로 기록한다. 동의 기록 없이 계정만 생기거나, 실패한 가입의 기록이 남지 않게 하기 위해서다. 이메일 가입은 `SignupService.signup`, 카카오 가입은 가입 단계 화면(M1-c)에서 기록한다.
4. 수집 최소화 원칙에 따라 IP·브라우저 정보는 기록하지 않는다(PRD에 없음).
5. 탈퇴 계정을 파기할 때 함께 지운다(`ON DELETE CASCADE`, ADR-015).
6. **약관 버전이 바뀔 때 재동의는 이번 범위에서 제외**한다. 버전을 기록해 두었으므로 나중에 "로그인 후 지금 버전에 동의했는지 확인 → 재동의 화면"을 붙일 수 있다(`ix_consent_log_landlord`).

## 검토한 대안
| 대안 | 채택하지 않은 이유 |
|---|---|
| landlord 테이블에 동의 시각 컬럼 | 문서별·버전별 이력을 남길 수 없다 |
| 체크 여부만 기록(버전 없음) | 약관이 바뀌었을 때 누가 어느 버전에 동의했는지 알 수 없다 |
| 탈퇴 후에도 동의 기록 보관 | 보관해야 할 법적 근거를 확인하지 못했다. 카카오 정책도 탈퇴 시 모든 개인정보 파기를 요구한다. 출시 전 전문가 검토 항목으로 남긴다 |

## 결과
- 출시 전 전문가 검토 항목: **동의 기록의 법적 보관 의무**(탈퇴 후에도 남겨야 하는지, 남긴다면 얼마나). 결과에 따라 파기 정책을 바꿀 수 있다(docs/progress.md "출시 전 전문가 검토"). 전문가 검토는 배포 후 개발자 본인 테스트를 마친 뒤로 보류했다(2026-10-17).
- 개발 중에 만든 계정(M1-a·b)에는 동의 기록이 없다. 실제 사용자는 출시 후에 생기므로 따로 채우지 않는다.
