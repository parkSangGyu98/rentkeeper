# ADR-032: 화면 디자인 — 옅은 회청색 바탕·흰 카드·짙은 남색 한 색, 토큰은 app.css 한 곳

- 상태: 승인됨 (디자인 교체, 2026-10-24 개발자 결정 "섞은 안")
- 날짜: 2026-10-24

## 맥락
- 처음 화면은 40~60대 가독성(큰 글씨·두꺼운 선·높은 대비)만 보고 만들어 "저렴해 보인다"는 평가를 받았다. 이 서비스는 포트폴리오용이라 첫인상이 세련돼야 한다.
- 목표: 나이를 가정하지 않고 "건물을 운영하는 사람에게 어울리는 차분하고 정돈된 금융 앱 느낌". 읽기 기준(16px 미만 금지, 본문 대비 4.5:1 이상, 터치 48px 이상, 상태는 색+글자+아이콘)은 유지한다.
- 화면이 70개 가까이 되고, 템플릿마다 Tailwind 낱말(`border-2`, `text-3xl font-bold` 등)을 직접 적어 한 번에 바꾸기 어려웠다.

## 결정
- **시안 비교 뒤 섞은 안**: 대시보드 한 화면으로 A안(흰 바탕·짙은 남색·선과 여백, `fb0c94b`)과 B안(옅은 회청색 바탕·흰 카드·옅은 그림자·밝은 파랑, `6cec03f`)을 비교했다. B안을 기본으로, 포인트 색만 A안의 짙은 남색 `#1f3a64`로 한다.
- **값은 `app.css`의 `@theme` 한 곳**: 페이지 바탕 `#f2f5f9`, 선 `#e3e8ef`, 카드 그림자, 모서리 12px, 남색과 파생 단계(50·100·200·800·900), 채도 낮춘 위험 색 `#9b2c2c`, 글자 단계(라벨 16px·카드 제목 20px·화면 제목 28px·금액 36px·세입자 금액 40px), 굵기 2단계(400·600, `font-bold`도 600), 간격 단위 4px(`--spacing`).
- **템플릿은 공통 클래스 이름만**: `page`·`page-wide`·`page-tenant`, `page-head`·`page-title`, `card`(`-attention`·`-empty`·`-accent`·`-danger`), `btn`(`-primary`·`-secondary`·`-quiet`·`-selected`·`-danger`·`-danger-secondary`·`-lg`), `badge-*`, `form-*`, `alert-*`, `banner`, `stat-*`, `row-*`, `kv-list`, `facts`, `item-row`, `summary-grid`·`list-grid`, `hero`·`feature-*`. 배치용 Tailwind 낱말(`flex`·`gap-*`·`mb-*`)만 템플릿에 남긴다.
- **버튼 위계**: 꽉 찬 남색 버튼은 화면당 주요 행동 1개. 다른 행동이 주요 행동이 되면 조건(`th:class`)으로 윤곽선으로 바꾼다(신고가 있으면 [다 받았어요], 이번 달 받을 월세가 없으면 [세입자 링크 만들기], 건물이 없으면 [건물 추가], 데모가 켜져 있으면 [무료로 가입하기]). 고른 탭은 꽉 찬 버튼이 아니라 `btn-selected`. 위험 행동으로 가는 버튼·링크는 채도 낮은 빨강(`btn-danger-secondary`·`link-danger`), 되돌릴 수 없는 최종 버튼은 `btn-danger`.
- **상태 뱃지**: 옅은 바탕 + 진한 글자 + 작은 아이콘. 포인트 색과 겹치지 않게 의미 색을 채도 낮게(받을 차례·입주 예정은 남색 대신 청회색). 글자 대비 7:1 이상.
- **화면 폭**: 폼·확인 화면은 모든 폭에서 좁게, 목록·상세·대시보드는 lg부터 `max-w-6xl`(카드 두 칸·요약 한 줄), 세입자 화면은 모든 폭에서 한 단(`max-w-xl`). `<table>`은 만들지 않는다.
- **머리글**: 좁은 화면 [메뉴]는 펼쳐도 로고 옆에 남고 메뉴 상자가 머리글 아래로 겹쳐 펼쳐진다. 로그인 전에는 로그인=글자 버튼, 가입하기=윤곽선.
- **한글 줄바꿈**: 본문에 `word-break: keep-all`(낱말 중간에서 줄을 바꾸지 않음), 아주 긴 낱말만 `overflow-wrap`으로 끊는다.

## 검토한 대안
| 대안 | 채택하지 않은 이유 |
|---|---|
| A안 그대로(흰 바탕, 선과 여백) | 카드 경계가 약해 화면이 넓을수록 정보 묶음이 흐려진다 |
| B안 그대로(밝은 파랑) | 머리글·초점 외곽선의 남색과 섞여 두 가지 포인트 색이 된다 |
| 화면마다 Tailwind 낱말 유지 | 값을 바꿀 때마다 70개 템플릿을 고쳐야 한다 |
| 컴포넌트 라이브러리(daisyUI 등) 도입 | 새 의존성, 외부 주소 없이 넣고 CSP를 맞추는 비용, 화면 문구·구조와 맞지 않는 기본값 |

## 결과
- 커밋: 시안 `fb0c94b`·`6cec03f`, 공통 스타일 확정 `b0c465e`, 화면 묶음 `2a55afc`(대시보드·받을 월세), `0207baa`(계약·건물·호실), `80c5213`(세입자), `d64e0be`(첫 화면·로그인·가입·데모), `98c7dfb`(알림·설정), `bbede93`(확인·수정·오류·약관).
- 바뀐 테스트: `DashboardTests`·`ChargeListTests`의 금액 `dd`·`dt` 클래스만(같은 강도). 화면 문구·동작은 바꾸지 않았다.
- 브라우저에서 잰 값(섞은 안 대시보드): 본문 최저 대비 9.42:1, 라벨 9.42:1, 버튼 11.37:1, 가장 작은 글자 16px, 버튼·입력칸 높이 54px.
- 남은 일: 360·375px과 글자 200%는 사람 확인(progress "배포 직전 사람 확인 목록"). 세입자 링크 화면은 링크 원문에 자동화를 쓰지 않아 사람이 확인한다.
