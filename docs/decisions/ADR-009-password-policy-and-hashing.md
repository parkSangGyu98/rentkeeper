# ADR-009: 비밀번호 규칙과 해시

- 상태: 승인됨
- 날짜: 2026-10-17

## 맥락
- PRD AUTH-1: 비밀번호 BCrypt, 최소 8자. PRD 8.1: BCrypt strength 10 이상.
- 주 사용자는 40~60대 임대인이다. 복잡한 조합 규칙(대문자·숫자·특수문자 필수)은 비밀번호를 적어 두거나 재사용하게 만들어 오히려 위험하다.
- BCrypt는 입력의 앞 72바이트만 쓴다. Spring Security 7.1.1의 `BCrypt`는 72바이트를 넘으면 `IllegalArgumentException`("password cannot be more than 72 bytes")을 던진다 (소스 확인).
- 한글은 UTF-8에서 한 글자에 3바이트다.

## 결정
1. **규칙은 NIST SP 800-63B 방식**으로 한다. 길이와 흔한 비밀번호 차단을 보고, 문자 조합은 강제하지 않는다.
   - 8자 이상 (글자 수 기준, 한글 1글자 = 1자)
   - UTF-8 **72바이트 이하** (영문·숫자 72자, 한글 24자). 넘으면 "너무 길어요"로 안내한다. 잘라서 저장하면 사용자는 모르는 채로 뒷부분이 무시되므로 자르지 않는다.
   - 흔한 비밀번호 목록(`src/main/resources/auth/common-passwords.txt`, 직접 정리한 약 100개, 대소문자 무시)에 없을 것
   - 이메일 주소 또는 이메일 `@` 앞부분과 같지 않을 것
   - 한 글자만 반복하지 않을 것 (`aaaaaaaa`)
2. **해시는 BCrypt cost 12**, `DelegatingPasswordEncoder`로 저장값에 `{bcrypt}` 접두사를 붙인다. 나중에 알고리즘이나 cost를 바꿔도 기존 해시를 구분해 검증할 수 있다.
3. 평문 비밀번호는 auth 모듈 밖으로 나가지 않는다. landlord 모듈은 해시만 받는다.
4. 평문이 로그에 남지 않게 한다.
   - `SignupForm.toString()`에서 비밀번호를 감춘다(record 기본 toString은 모든 값을 출력한다).
   - 예외 메시지에 비밀번호를 넣지 않는다.
   - 로그인 직후 principal의 해시를 지워 세션(DB)에 저장되지 않게 한다.
   - 오류가 나도 비밀번호 입력칸은 다시 채우지 않는다.
   - `PasswordNotLoggedTests`가 DEBUG 로그를 켠 상태에서 가입·로그인 성공/실패를 수행하고, 출력에 원문 비밀번호가 없는지 확인한다.

## 검토한 대안
| 대안 | 채택하지 않은 이유 |
|---|---|
| cost 10 (PRD 최소, Spring 기본값) | 하드웨어가 빨라질수록 여유가 줄어든다. 12도 로그인 1회에 수백 ms 수준으로 사용자 체감에 문제없다 |
| 문자 조합 규칙 강제 | 사용자 부담만 늘고 실제 강도는 크게 높아지지 않는다 (NIST 권고와 반대) |
| 외부 대형 유출 목록(수백만 건) | 라이선스·용량 문제. MVP에서는 가장 흔한 것만 막고, M1-b의 로그인 잠금·IP 제한으로 무차별 대입을 막는다 |
| 72바이트 초과분을 잘라서 해시 | 사용자 모르게 뒷부분이 무시된다. 명확히 안내하는 편이 낫다 |
| Argon2 | 메모리 하드 해시로 더 강하지만, 작은 VM(t4g.small급)에서 메모리 사용량을 따로 조정해야 한다. 필요해지면 `{argon2}`로 옮길 수 있다 |

## 결과
- **M6에서 운영 서버의 해시 시간을 측정한다** (docs/progress.md 출시 전 할 일). 너무 느리면(대략 1초 이상) cost를 다시 검토한다.
- 흔한 비밀번호 목록은 수동으로 관리한다. 운영 중 자주 쓰이는 약한 비밀번호가 보이면 추가한다.
- 로그인 무차별 대입 방어(5회 실패 시 15분 잠금 + IP 레이트 리미트)는 M1-b에서 한다.
